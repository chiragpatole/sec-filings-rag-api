# Filing Room — SEC Filings RAG API

A retrieval-augmented Q&A API over **real** SEC EDGAR 10-K/10-Q filings. Ask a question like *"What supply chain risks does Apple disclose?"* and get a grounded answer, generated by Claude, citing the specific filing it came from — not a hallucinated summary.

Built end-to-end: real data ingestion, a from-scratch cleaning/chunking pipeline, vector search, an LLM generation layer, a containerized backend, and a live deployment on AWS.

## What it does

1. Pulls real 10-K and 10-Q filings for Tesla, Apple, and Microsoft directly from the [SEC EDGAR API](https://www.sec.gov/edgar/sec-api-documentation)
2. Cleans the raw HTML, isolates the Risk Factors section, and splits it into sentence-safe chunks
3. Embeds each chunk and indexes it in a local FAISS vector store
4. On a query: retrieves the most relevant chunks, deduplicates near-identical text repeated across a company's quarterly filings, and sends the result to Claude to generate a grounded, cited answer
5. Serves all of this through a FastAPI backend, containerized with Docker, deployed on AWS ECS Fargate

## Architecture

```
EDGAR API ──▶ edgar_ingest.py ──▶ raw HTML filings
                                        │
                                        ▼
                              build_index.py
                    (HTML clean → section extract → chunk → embed)
                                        │
                                        ▼
                              FAISS vector index
                                        │
                                        ▼
                    FastAPI (main.py + retrieval.py)
                    /health   /query (retrieve → generate)
                                        │
                              ┌─────────┴─────────┐
                              ▼                   ▼
                        Docker image      Claude (Anthropic API)
                              │
                              ▼
                    AWS ECR → ECS Fargate
                              │
                              ▼
                  index.html (browser UI) ──▶ live public endpoint
```

## Stack

- **Data**: SEC EDGAR full-text API (public, no auth)
- **Retrieval**: `sentence-transformers` embeddings + FAISS
- **Backend**: FastAPI
- **Generation**: Claude Haiku 4.5 via the Anthropic API
- **Infra**: Docker, AWS ECR, AWS ECS Fargate
- **UI**: single-file HTML/JS, no framework

## Running it locally

```bash
python -m venv venv
source venv/bin/activate
pip install -r requirements.txt

# 1. Pull real filings from EDGAR
python Edgar_ingest.py

# 2. Clean, chunk, embed, build the FAISS index
python build_index.py

# 3. (optional) sanity-check retrieval from the command line
python query_index.py

# 4. Set your Anthropic API key and start the API
export ANTHROPIC_API_KEY=sk-ant-...
uvicorn main:app --reload
```

Open `http://127.0.0.1:8000/docs` for the interactive API, or open `index.html` directly in a browser (point the "API endpoint" field at wherever the API is running).

## Running it in Docker

```bash
docker build --platform linux/amd64 -t sec-filings-api .
docker run -p 8000:8000 -e ANTHROPIC_API_KEY=sk-ant-... sec-filings-api
```

## Deploying to AWS

`task-definition.json` is a ready-to-use ECS Fargate task definition. Replace `REPLACE_WITH_YOUR_KEY` with a real Anthropic API key (or better, wire it to AWS Secrets Manager instead of a plaintext env var for anything beyond a demo), push the image to ECR, and register it:

```bash
aws ecr get-login-password --region us-east-1 | docker login --username AWS --password-stdin <account-id>.dkr.ecr.us-east-1.amazonaws.com
docker tag sec-filings-api:latest <account-id>.dkr.ecr.us-east-1.amazonaws.com/sec-filings-api:latest
docker push <account-id>.dkr.ecr.us-east-1.amazonaws.com/sec-filings-api:latest

aws ecs register-task-definition --cli-input-json file://task-definition.json --region us-east-1
aws ecs update-service --cluster <cluster> --service <service> --task-definition sec-filings-api --force-new-deployment --region us-east-1
```

## Notes on design decisions

- **FAISS instead of a managed vector database.** AWS OpenSearch Serverless carries a large fixed hourly cost regardless of usage, which doesn't make sense for a small demo dataset. FAISS bundled directly in the container is a legitimate choice at this scale, and the tradeoff (no managed scaling, no separate persistence layer) is worth naming explicitly if you're evaluating this project.
- **Generation via the Anthropic API rather than Bedrock.** This was originally built against Amazon Bedrock; a new-account Bedrock quota approval got stuck pending AWS Support review for 24+ hours with no ETA, so generation was switched to call the Anthropic API directly instead. Same model, same prompt — different client. The Bedrock integration code path is easy to restore if needed.
- **Sentence-boundary-aware chunking.** An earlier version split text purely on HTML block boundaries and fixed word counts, which repeatedly cut real sentences in half mid-thought (confirmed against actual filing text — see `debug_chunk.py`). The current pipeline rejoins HTML blocks that don't end in terminal punctuation and splits long paragraphs only at sentence boundaries.
- **Deduplication at query time.** SEC filings frequently carry identical boilerplate risk-factor language forward unchanged across a company's quarterly filings. Without deduplication, one repeated sentence can crowd out 4 of the top 5 retrieved results. `retrieval.py` searches for more candidates than requested and keeps only the highest-ranked occurrence of each near-identical chunk.

## What this doesn't (yet) do

- No conversation memory — each query is independent
- No support for filing types beyond 10-K/10-Q, or companies beyond the three preloaded
- No authentication on the API — fine for a demo, not for anything public-facing with real usage
